# 侧栏菜单的展开与定位设计

本文描述面向 **v1.6.2 协调发行目标的导航改进**。设计目标是让菜单随业务增长仍然易于浏览，
不表示已发布的 v1.6.1 具有本文行为，也不构成验证通过或发布完成的声明。
机器契约位于仓库 `.mss/features/admin-sidebar-navigation.yaml`。

## 问题与方向

目录及其全部子项同时铺开，会让常用入口淹没在长列表里。单纯把整条侧栏缩成图标，
又会降低入口的可辨识性。此次保留已有侧栏，用可折叠目录组织业务入口：初始只显示
当前路径所需的层级，用户展开其他一级目录时收起上一目录。

默认首页、列表和详情页仍使用现有路由与权限数据。菜单顺序、名称、归属及业务权限
不随此次调整改变；菜单搜索继续作为已知目标的快捷入口。

## 参考与取舍

| 参考 | 可借鉴的做法 | 本次选择 |
| --- | --- | --- |
| [Ant Design Menu](https://ant.design/components/menu/) | 官方提供“仅展开当前子菜单”的紧凑导航示例，也支持侧栏折叠与标题提示。 | 采用一级目录手风琴，保留原组件的键盘和选中行为。 |
| [ProLayout](https://procomponents.ant.design/components/layout/?tab=api) | 提供 `sub` / `group` 菜单类型、默认展开和自动关闭选项。 | 显式选择可折叠的 `sub`，关闭全部展开，复用路由定位；一级目录点击另用公开属性约束。 |
| [Vben Admin](https://doc.vben.pro/guide/essentials/settings.html) | 导航配置采用手风琴模式；目录点击是否自动激活子项是独立配置，示例默认关闭。 | 目录点击只负责开合，具体页面由用户选择。 |

RuoYi 的[侧栏默认展开说明](https://doc.ruoyi.vip/ruoyi-vue/other/faq.html#侧边栏如何默认展开)
也通过指定目录键来控制展开范围。它的示例允许多个目录同时展开，因此这里不把
“所有后台项目都使用手风琴”作为依据，而是针对本项目菜单过密的问题作出选择。

本次不增加收藏、最近访问、双列菜单或新的顶部导航。它们涉及新的信息组织和状态，
不能替代目录展开行为本身的修正。已有搜索继续使用同一份有权限的菜单数据。

## 交互规则

| 场景 | 预期行为 |
| --- | --- |
| 首次进入 | 展开当前页面的祖先目录，其余目录保持收起；无祖先目录的入口不额外展开其他分支。 |
| 点击目录标题 | 只展开或收起，不跳转到第一个子页面。 |
| 展开另一个一级目录 | 收起原先的一级目录，当前页面的选中信息仍由路由维护。 |
| 手动收起当前目录 | 尊重此次操作，普通重渲染不强制重新打开。 |
| 切换页面、刷新或打开深链接 | 由现有路由匹配展示当前页面所属路径，不展开无关目录。 |
| 搜索后进入页面 | 搜索沿用现有入口，页面选中与祖先目录由同一套布局逻辑同步。 |
| 折叠整条侧栏 | 保留图标、标题提示和浮层子菜单；恢复侧栏后不能全部展开。 |
| 窄屏使用 | 沿用移动导航容器，可打开目录、选择页面并关闭导航，避免挤压正文。 |

详情页不必新增菜单项。若既有路由已经指定对应列表或父级的选中关系，继续使用该关系；
不在这次调整中建立另一套路由匹配规则。Vben 的
[`activePath` 设计](https://doc.vben.pro/en/guide/essentials/route.html#activepath)
也体现了详情页与导航入口可以分开的思路。

## 实现边界与视觉

菜单行为保留在现有 ProLayout 中，基础配置为：

```ts
menu: {
  type: 'sub',
  defaultOpenAll: false,
  // 不设置 autoClose，保留默认的路由自动关闭行为。
}
```

`group` 是分组展示，`sub` 才能提供目录开合。因此仅修改 `defaultOpenAll`，
不足以保证原来分组展示的菜单变为可折叠目录。仓库锁定版本的 `autoClose` 只在路由
变化时关闭其他目录，不能独自实现点击一级目录时的手风琴行为。该版本的类型只接受
`autoClose: false` 作为关闭此行为的开关，因此实现保留默认值。

为补齐这一点，在公共 `menuContentRender` 插槽中使用轻量适配组件，通过公开的
`openKeys` 与 `onOpenChange` 约束一级目录展开。菜单渲染、路由匹配和权限数据仍由
原有 ProLayout 流程负责。适配组件不另造菜单树、不复制路由匹配算法，也不引入新依赖。
实际菜单中的目录可以没有页面地址。适配器根据组件回传的已匹配叶子键，从授权菜单树
补全祖先目录，并只保存目录的展开状态。这既兼容无地址目录，也允许用户手动收起当前
分支。手机端选择页面时调用原组件的菜单点击回调，关闭导航抽屉。

保留现有 **232px 侧栏、36px 菜单行高、系统字体和品牌蓝色 token**。当前页面沿用
选中背景与文字颜色，目录沿用图标与展开箭头；不增加装饰性卡片、额外标签或新的主题。
明暗主题及用户品牌色继续由既有主题系统决定。

不增加持久化展开键、应用主题字段或个人主题字段。后端菜单树、可见性筛选、搜索数据源
和接口授权保持现有边界。前端目录是否展开不授予任何访问权限。本次无需数据库迁移。

## 验收与采用

实施后按机器契约运行定向前端检查、TypeScript、生产构建及文档构建，并在内置浏览器
验证以下场景。此表是验收要求，不是已执行的结果。

| 验收项 | 完成标准 |
| --- | --- |
| 多目录与三级菜单 | 初始不全部展开；一级切换、嵌套展开与手动收起均符合交互规则。 |
| 路由定位 | 深链接、刷新、前进后退、菜单搜索后都能识别当前页面所属目录。 |
| 侧栏与移动端 | 桌面折叠恢复不全部展开；390 × 844 窄屏可以完成打开、选择和关闭。 |
| 权限与可访问性 | 只显示已有权限允许的入口，键盘焦点可见，折叠后仍能识别入口。 |
| 视觉与语言 | 1440 × 900 桌面及窄屏布局无溢出，中文、英文和明暗主题可读。 |

当前源码已应用上述行为，并在 `web/antd-v6/src/shared/layout/SidebarMenu.test.tsx`
覆盖实际 ProLayout 交互、无地址目录及跨分组路径前缀。下一步通过面向 `main` 的 PR
评审该实现，并在发行前完成验收矩阵中尚未覆盖的项目。正式采用需核验 v1.6.2 的发布产物；
不重写或重新发布已有的 v1.6.1 制品。
