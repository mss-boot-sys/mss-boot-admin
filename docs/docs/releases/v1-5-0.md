# v1.5.0 后台登录与令牌安全加固

> 历史记录：本页保留原 v1.5.0 发行的版本事实，不定义当前发布状态。当前入口见 [v1.6.1 发布说明](/releases/v1-6-1)与[快速开始](/getting-started)。

v1.5.0 是 v1.4.0 之后的
向后兼容次版本：没有数据库结构迁移，新增的安全控制默认关闭或兼容旧行为；唯一删除的是
API 根路径下未鉴权的死存根路由。本页描述本次发行合同；是否已完成发布，以对应 Release、
包、镜像和公开网站的实际结果为准。

## 变更范围

- **后台登录白名单** `auth.adminLogin.allowlist`：GitHub 只按数字用户 ID 匹配，飞书按 open id；
  名单外身份在建号和签发令牌前被拒绝（403），本地密码登录不受影响。
- **登录限流** `auth.adminLogin.rateLimit` 与客户端 IP 规则 `auth.adminLogin.clientIP`：
  按 IP 限制密码登录与 OAuth 回调，超限 429；转发头只在直连对端是可信代理时采用。
- **令牌受众**：会话令牌与 PAT 写入 `iss` 和 `aud=admin`；其他受众（如 `portal`、`user`）的令牌
  即使用同一把密钥签名也会被后台拒绝（401）。没有 `aud` 的旧令牌在兼容模式下仍可用，
  `auth.requireAdminAudience: true` 开启严格模式。
- **框架** `mss-boot/pkg/keyedlimit`：按 key 限流的接口、内存实现与可复用契约测试。
- **API 基线快照**：路由表、安全路由契约与 OpenAPI 操作摘要纳入测试，非预期变化会失败。
- **删除死存根路由**：`GET/POST /admin/api` 与 `GET/PUT/DELETE /admin/api/:id`（无资源，
  部分未鉴权返回 501），现在返回 404。

详细配置与安全说明见[安全基线](/admin/security-baseline)。

## 从 v1.4.0 升级

1. 备份代码、配置、数据库和当前可运行镜像，并安装 v1.5.0 工具，核对 `mss --version` 与
   `mss-mcp --version`；确认 `.mss/blueprint-manifest.json` 存在，保留旧基线以执行三方合并。
2. 按只读计划、应用、完整验证和最终空计划执行：

```shell
mss upgrade admin v1.5.0 --format json
mss upgrade admin v1.5.0 --apply --yes --format json
mss doctor --strict
mss verify --all
mss upgrade admin v1.5.0 --format json
```

最终计划必须无 create、update、delete 或 conflict。手工拼装或丢失 manifest 的项目应在新目录
生成 v1.5.0 基线，再迁入业务规格、配置与自有文件，不要伪造旧摘要或提交本地 `replace`。

3. 不改配置时行为与 v1.4.0 一致；按需开启白名单、限流和可信代理规则。
4. 计划开启 `auth.requireAdminAudience` 前，重新签发或撤销 v1.5.0 之前创建的 PAT，并等待升级前的
   浏览器会话过期，步骤见[安全基线](/admin/security-baseline)。

无需数据库迁移。

Admin Web → Root 顺序打标签，最后发布 `docs/v1.5.0` 并检查线上 `/release.json`。
