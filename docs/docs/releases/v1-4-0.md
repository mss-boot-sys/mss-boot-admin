# v1.4.0 UI 刷新与生成器升级

> 历史记录：本页保留原 v1.4.0 发行的版本事实，不定义当前发布状态。当前入口见 [v1.5.0 发布说明](/releases/v1-5-0)与[快速开始](/getting-started)。

v1.4.0 是 v1.3.9 首发之后的
向后兼容次版本：没有删除或重命名 API，也没有数据库结构迁移。本页描述本次发行合同；
是否已完成发布，以对应 Release、包、镜像和公开网站的实际结果为准。

所有核心组件绑定同一经过本地完整验证的 merged `main` 提交。

## 变更范围

- **Admin Web UI 刷新**：路由标签页、列表 CSV 导出、筛选标签、列与密度设置、最近登录列、
  用户统计卡片、紧凑页脚，侧栏顶级目录显示为分组标题。
- **默认主题改为浅色**（之前为深色）。已保存的个人主题保持不变；需要默认深色时，在应用或
  个人主题设置中设置 `navTheme: realDark`。
- **行操作改为「编辑 + ⋯」**：内置列表和生成页的次要操作（详情、删除等）进入 `⋯` 菜单，
  权限隐藏/禁用规则不变，危险操作仍需确认。
- **403 页面**：路由级无权限页面保留布局头部与宿主 header 扩展，并使用设计系统的
  `PageForbidden`；侧栏桌面头部按断点渲染，宿主 header 扩展在 DOM 中只出现一次。
- **新增 API**：仅 root 可用的 `GET /admin/api/user/overview?ids=`（`weekNew`、
  `onlineSessions`、`lastLogin`）；`GET /admin/api/users` 新增可选的 `roleID` /
  `departmentID` 精确筛选。均来自已有表字段，无迁移。
- **生成器**：前端模板 `1.3.0-frontend-v6.8`、e2e 模板 `1.3.0-e2e-v6.10`。
- CI 与发布工作流的 Actions 固定版本升级（setup-node v7.1.0、download-artifact v8.0.2）。

## 从 v1.3.9 升级

1. 备份代码、配置、数据库和当前可运行镜像，并安装 v1.4.0 工具，核对 `mss --version` 与
   `mss-mcp --version`；确认 `.mss/blueprint-manifest.json` 存在，保留旧基线以执行三方合并。
2. 按只读计划、应用、完整验证和最终空计划执行：

```shell
mss upgrade admin v1.4.0 --format json
mss upgrade admin v1.4.0 --apply --yes --format json
mss doctor --strict
mss verify --all
mss upgrade admin v1.4.0 --format json
```

最终计划必须无 create、update、delete 或 conflict。手工拼装或丢失 manifest 的项目应在新目录
生成 v1.4.0 基线，再迁入业务规格、配置与自有文件，不要伪造旧摘要或提交本地 `replace`。

3. 重新生成的模块页面和生成 e2e 会变化：业务自写的 e2e 若直接点击行内「详情」「删除」
   按钮，需要先打开 `More actions`（`⋯`）再点击菜单项。
4. 依赖 header 扩展隐藏副本的测试需要更新：桌面端与移动端各只渲染一次。
5. 检查假定深色背景的自定义样式。

无需数据库迁移；仍建议升级后运行一次 `server -a` 同步 API 权限，使新的
`/user/overview` 路由进入权限表。

## 发布与验证

源码变更通过 PR 合入 `main` 后冻结精确提交，执行完整本地验证，再按 Framework → Admin →
Admin Web → Root 顺序打标签，最后发布 `docs/v1.4.0` 并检查线上 `/release.json`。
